Overview of Docker Objects
Docker utilizes several core objects and components to manage containerized applications:

Dockerfile: A text file containing sequential instructions required to build a container image.

Docker Images: Read-only templates used to create container instances.

Docker Containers: Runnable instances of Docker images.

Networks: Communication channels that isolate container traffic.

Storage Volumes & Bind Mounts: Mechanisms used to persist data beyond a container's lifecycle.

Plugins & Add-ons: Extensions (such as storage plugins) that connect Docker to external systems and platforms.

Essential Dockerfile Instructions
You can create a Dockerfile using any text editor or terminal. Key instructions include:

FROM: Defines the base image for the container (e.g., an operating system or a language runtime like Node.js or Go). A Dockerfile must always begin with a FROM instruction.

RUN: Executes build commands inside the container image layer.

CMD: Defines the default command to execute when running the container. A Dockerfile should contain only one CMD instruction; if multiple are present, only the last CMD instruction takes effect.

Docker Images & Layering
Read-Only Templates: Images consist of read-only layers generated by each instruction in a Dockerfile.

Layer Caching & Efficiency: When a Dockerfile is modified and rebuilt, the Docker engine only rebuilds the modified layers. Shared layers across images save disk space and network bandwidth.

Writable Container Layer: When an image is instantiated into a running container, a writable layer is added on top of the read-only image layers, enabling runtime state changes.

Container Image Naming Convention
An image name follows a standardized three-part format: hostname/repository:tag

Hostname: Identifies the registry hosting the image (e.g., docker.io for Docker Hub). The CLI defaults to docker.io if omitted.

Repository: A group of related container images (e.g., ubuntu).

Tag: Identifies a specific version or variant of the image (e.g., 18.04).

Example: In docker.io/ubuntu:18.04, docker.io is the registry host, ubuntu is the repository, and 18.04 is the version tag.

Docker Containers
A container is a runnable instance of an image created, started, stopped, or deleted using the Docker CLI or API.

Containers maintain high isolation from each other and the host machine.

You can attach network interfaces, mount external storage, or commit a container's current state to a new image.

Networking, Storage, & Plugins
Networks: Used to isolate and manage communications between containers and external networks.

Storage Persistence: By default, container data is volatile and lost upon container deletion. Docker uses volumes and bind mounts to persist data independently of the container lifecycle.

Plugins: Extend Docker capabilities, such as storage plugins that connect containers to external storage platforms.
